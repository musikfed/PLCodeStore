# PL Code Store — GitHub-first автоматизация

Публичная витрина: https://musikfed.github.io/PLCodeStore/
Решение автора: https://musikfed.github.io/PLCodeStore/review/

## Основное правило

**Автор одобряет не через Issue и не через редактирование JSON.**
Для публичных проектов ❤️ открывает штатный Pull Request в **исходном репозитории**.
Автор проверяет результат и нажимает **Merge pull request → Confirm merge**.
Только в этот момент запрос `publication: "publish_on_merge"` вступает в силу. Пока PR открыт, проект **не опубликован**.

GitHub Pages не имеет личного токена в браузере: прямое однокликовое авторизованное объединение PR с обычного статического сайта невозможно без отдельного OAuth-приложения или серверного посредника. Поэтому остаётся одно штатное подтверждение **Merge** на стороне GitHub. Служебные Issues больше не используются.

## Интерфейс Review Studio

- **На проверке:** только открытые реальные PR из публичных репозиториев, не отложенные автором.
- **Переданы на подтверждение или доработку:** карточки, для которых автор открыл GitHub PR для Merge или отметил доработку в данном браузере. Это не равно факту публикации.
- **Уже на витрине:** одобренные проекты, присутствующие в собранном публичном `data/projects.json`.
- **Обновить список / проверить PR:** перечитать опубликованный JSON и выборочно проверить статус не более 5 отмеченных PR с локальным таймаутом 60 секунд, без постоянного фонового опроса.
- **Три обязательные галочки:** корректность названия/описания, корректность изображения/обложки, разрешение публиковать информацию.
- **Замечания необязательны:** если есть текст, он копируется в буфер, открывается окно комментария внутри PR. Пользователь самостоятельно отправляет комментарий. При пустом тексте пометка «На доработку» сохраняется только в браузере.
- **Пропустить на потом:** локальное отложение с возможностью восстановить карточку.
- **Следующая:** перелистывание без изменения состояния.

После Merge PR перестаёт быть открытым, поэтому исчезает из собранной очереди, а карточка появляется в публичном каталоге при следующей сборке Pages. Если автор нажал ❤️ и закрыл PR без слияния, статус остаётся «Ожидает Merge», и карточку можно вернуть на проверку.

## Где и как выполняются задачи

1. `Discover` (`.github/workflows/discover.yml`) определяет изменения в репозиториях и создаёт PR с папкой `vitrine/`. Работа проходит на серверах GitHub Actions.
2. В **публичном** PR `publication: "publish_on_merge"`: это не публикация, а заранее подготовленная инструкция для момента Merge. Файлы приложения не трогаются.
3. Автор просматривает карточку и объединяет PR на GitHub — это явное разрешение.
4. `Pages` (`.github/workflows/pages.yml`) читает одобренные `vitrine/meta.json` из **default branch** исходных репозиториев, собирает статический сайт. `view_my_prj` не используется как источник.
5. Закрытые репозитории не отображаются в публичной Review Studio. Для них сохраняются отдельные требования `publication: approved` и `public_private_approved: true`, которые автор устанавливает в закрытом PR перед Merge. В публичный каталог не попадают приватные исходники и изображения; создаётся графическая обложка.

## Токены и ограничения

Один персональный `PL_CODESTORE_TOKEN` хранится только в **PLCodeStore → Settings → Secrets and variables → Actions**. Он нужен для создания предложений в разных репозиториях и чтения закрытых проектов, но не передаётся посетителю Pages. Создавать второй токен не требуется.

- В один запуск Discover: максимум 6 новых PR, до 60 просматриваемых репозиториев и бюджет 350 запросов API.
- После первой инвентаризации используются кэш истории изменений, выборочный обход и контрольный аудит. Повторные PR с той же веткой не создаются.
- Pages запускается после успешного Discover, при изменениях PLCodeStore, по расписанию и вручную.
- **Слияние PR из другого репозитория не вызывает мгновенную сборку PLCodeStore.** Это штатное ограничение GitHub Actions: публикация состоится при следующем запуске Pages. Если нужен результат сразу, автор может открыть [Build and deploy PL Code Store Pages](https://github.com/musikfed/PLCodeStore/actions/workflows/pages.yml) и нажать Run workflow.
- Отсутствует постоянный браузерный опрос, а выборочная проверка открытых PR ограничена небольшим числом запросов при нажатии «Обновить список».
- GitHub накладывает собственные лимиты на API и время выполнения Actions. Они не заменяют внутренний бюджет приложения.
