# PL Code Store · Автоматизация GitHub и решение автора

**Сайт:** https://musikfed.github.io/PLCodeStore/
**Решения автора:** https://musikfed.github.io/PLCodeStore/review/

Источники данных — **исключительно** `vitrine/meta.json` исходных репозиториев. Копирование из `view_my_prj` не используется; существующее портфолио и резюме не затрагиваются.

## Авторское решение — без ручного редактирования JSON

Review Studio показывает только публичные предложения и настоящие изображения исходных проектов.

Для публикации необходимо подтвердить **три** проверки:

1. Название и описание соответствуют проекту.
2. Визуальные материалы показывают проект корректно.
3. Информацию разрешено публиковать (нет секретов, личных контактов и чужих закрытых данных).

Комментарий/замечания **необязательны** и не считаются четвёртой проверкой.

- ❤️ **Одобрить:** открывается новая GitHub Issue с уже заполненными названием, SHA-версией предложения и всеми необходимыми сведениями. Автор, авторизованный на GitHub, нажимает **Submit new issue**. GitHub Actions проверяет личность владельца и точную версию PR, сам меняет `publication` на `approved`, затем пытается объединить только этот PR.
- 🛑 **На доработку:** открывается аналогичная подтверждаемая Issue. Actions оставляет необязательное замечание в исходном PR, не публикуя его и не переписывая код проекта.
- ◷ **Позже:** откладывает карточку локально в этом браузере, не изменяя GitHub.

Таким образом: **не надо открывать редактор `vitrine/meta.json`, менять строку и делать ручной Merge**. Дополнительное подтверждение **Submit new issue** остаётся обязательным: статический GitHub Pages не может безопасно отправлять авторизованные команды от имени посетителя самостоятельно.

После успешного решения GitHub Actions закрывает служебную Issue и публикует сообщение о результате. После завершения workflow Pages автоматически пересобирается. Если PR изменился после формирования карточки, действие отклоняется как устаревшее и автору предлагается обновить очередь. Если GitHub запрещает Merge конфликтами или обязательными проверками, Issue остаётся открытой с сообщением об ошибке; `main` не меняется.

**Закрытые проекты:** не выводятся в публичную очередь. Их надо рассматривать через закрытые PR; для публичной карточки нужен отдельный `public_private_approved: true`. Никакие приватные скриншоты не экспортируются в публичную очередь.

**Безопасность:** GitHub Issue создаётся только после подтверждения самим владельцем аккаунта; обработчик игнорирует решения других пользователей. Перед любым Merge повторно сверяется SHA коммита, принадлежность репозитория, ветка `plcodestore/vitrine-proposal`, базовая ветка, наличие `vitrine/meta.json` и отсутствие изменений за пределами `vitrine/`. Токен **не попадает в HTML/JavaScript**.

## Конвейер

1. **Discover** (`.github/workflows/discover.yml`) находит проекты, создаёт `vitrine/meta.json` и настоящие/генерируемые обложки в отдельных Pull Request.
2. **Pages** (`.github/workflows/pages.yml`) показывает черновики в Review Studio и публикует **только** одобренные карточки.
3. **Author decision** (`.github/workflows/author-decision.yml`) обрабатывает подтверждённую владельцем Issue.
4. После удачного решения **Pages** обновляется; ежедневная сборка остаётся страховкой.

GitHub Actions работают на серверах GitHub — локальная видеокарта, домашний сервер, LLM и Docker **не нужны**.

## Один токен

`PL_CODESTORE_TOKEN` хранится в **Settings → Secrets and variables → Actions** репозитория `PLCodeStore`, не на сайте. У него должны быть права `Contents: Read/Write` и `Pull requests: Read/Write` в выбранных исходных репозиториях. Для написания замечаний в PR также нужны права на комментарии PR/Issues. Встроенный `GITHUB_TOKEN` обслуживает создание комментариев и закрытие служебных Issues самого PLCodeStore.

## Нагрузка

- Первый обход: до 60 репозиториев, 350 API-запросов, до 6 новых PR за запуск.
- Затем: изменившиеся репозитории, незавершённые предложения и контрольный аудит раз в 14 дней; состояние хранится в Actions cache.
- GitHub Pages пересобирается после успешного Discover / авторского решения, при изменениях самого движка и по расписанию.
- GitHub дополнительно применяет собственные лимиты и ограничения Actions. Переполнение лимитов не требует ручного повторного запуска немедленно.
- Закрытые проекты никогда не выводятся в публичную Review Studio.
